# 障害対応の手順書（runbook）: github-ranking

困ったときに**上から順に読んで手を動かす**ための文書。ふだんの運用（起動・ログ・監視）は operations の文書や README に書き、ここには「起きたときの手順」だけを書く。

> **決まり**
> - 手を入れる前に、今の状態（時刻・エラーの文・影響を受けた人や範囲）を書き残す
> - **データが失われていないか**を最優先で確かめる
> - 課金が発生する操作・元に戻せない操作（データの復元・削除・本番への反映）は、**実行の直前に本人に確認**してから行う
> - 秘密の値（パスワード・トークン・接続文字列）は、この文書・チャット・Issue に貼らない

想定する障害ごとに、下の 1〜5 の節を1組で書く（障害が増えたら組を足す）。

## 6. バックアップと復元
| 対象 | 取り方・頻度 | 戻せる期間 | 復元の手順 | 戻すと失うもの |
|---|---|---|---|---|
| コード | Git（リモートが正本） | 全履歴 | 直前の版を出し直す |  |
| データ |  |  |  |  |
| 設定・秘密の値 | リポジトリに入れない。作り直す手順を書く | — |  |  |

- **戻す練習**: 復元の手順は、本番で使う前に一度ためす（練習した日: <!-- 日付 --> ／結果: ）。練習していない手順は「未確認」と書く
- 標準の機能で戻せない期間（例: 保存期間を過ぎた古い状態）があれば、ここに書いておく
