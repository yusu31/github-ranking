# 開発計画: github-ranking

実装の順番・工数の見積もり・実績の記録を持つ。範囲（必須／できれば／やらない）と削る順は [requirements.md](requirements.md) を正とし、ここには書き写さない。

> **数字はすべて推測から始める。** 見積もりは幅（下限〜上限）で書き、ぎりぎりの理想値を約束しない。最初の数件で実績を取り、台帳（4章）で見直す。

## 3. 確かめる日
見積もりが外れていないかを、日付を決めて確かめる。外れたときの動きを先に決めておく。

| 日 | 確かめること | 外れたときにすること |
|---|---|---|
|  | 最初の数件の実績から、1日あたりの進み方を出して全体を見直す | 合計を実績で直し、削る順を本人と決める |
