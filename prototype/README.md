# プロトタイプ: github-ranking

画面の見た目と動きを、本番の実装より先に確かめるための**使い捨て**の試作。

## 作る時期
**要件のたたき台（docs/requirements.md・docs/features.md の下書き）ができた後、基本設計の前。**
- 画面を見ながら要件を直す（足りない画面・いらない機能に気づく）
- 本人と「こういう物を作る」を目で合わせてから、基本設計（画面設計・API・データ）に進む

## 使い捨てであること
- 本番のコードに**流用しない**（作り方の質・構成を問わずに速く作るため）。本番は設計に沿って作り直す
- HTML・CSS・JS だけの静的なページでよい（ビルドもサーバーも不要）。データは仮のもの
- 大きく作り直したら版を分ける（例: `prototype/v2/`）。古い版は消さずに残し、最新の版をこの README に書く

最新の版: **prototype/v1/**（2026-11-12・Issue #9）

### v1 の見方
- `prototype/v1/index.html` をブラウザで開く（サーバー不要。フォントだけ Google Fonts から読む）
- 方向性は「星の朝刊」: 毎朝届く日報を紙の朝刊に見立てる。1位を一面の見出しに、お気に入りを「切り抜き」、Obsidian へ送るのを「切り抜き帳」から行う
- 画面の下の「見本」で状態を切り替える（通常／Trending 停止／取得失敗／要約なし／更新停止／送って8日）。本番には無い
- 日報の見本は `prototype/v1/daily-sample.md`
- データはすべて架空（`data.js`）。`evilcorp-demo/xss-sample` は、説明に HTML が混ざっても文字として出る（AC-37）ことの見本

## 実装の各 PR で見比べる
画面を作る・変える PR では、プロトタイプと実装を**並べて見比べ**、違いを一覧にする（機能別詳細設計の「プロトタイプとの見比べ」の表）。
- 違いは「直す」か「そのまま（理由）」に分ける。影響の大きい順に直す
- 見比べた画像は PR に貼る
- 実装の方が良くなった所は、プロトタイプを直さず、表に理由を書くだけでよい
