# 判断の記録（ADR）: github-ranking

ADR（Architecture Decision Record＝設計上の判断の記録）は、**1つの判断を1ファイル**に残す。採用した案だけでなく、**検討して却下した案と理由**も書く。あとから「なぜこうなっているのか」「前に比べた案は何か」を、会話を遡らずに辿れるようにするため。

## いつ書くか
- **技術選定**: ライブラリ・フレームワーク・外部サービス・データの置き場を選んだとき
- **方式の変更**: 一度決めた設計・手順・構成を変えたとき（前の ADR を置き換える）
- **やめた判断**: 作るのをやめた・使うのをやめた・試して見送ったとき（やらない理由も判断）
- 迷ったら書く。1つの ADR は短くてよい（数行の「状況」と「決定」でも、無いよりよい）
- 書かなくてよいもの: 名前の付け方など、すぐ直せて影響の小さい選択

## 番号の付け方
- ファイル名は `NNNN-短い名前.md`（4桁の通し番号。例: `0001-データベースの選定.md`）。最初の ADR は `0001`
- 新しく書くときは [0000-template.md](0000-template.md) をコピーする（`0000` は型なので番号に使わない）
- 番号は**使い回さない・欠番を詰めない**
- 決まった ADR の本文は**書き換えない**。判断を変えるときは新しい番号で書き、古い方の「状態」を「置き換え済み（ADR-NNNN）」に直すだけにする（誤字の修正は書き換えてよい）
