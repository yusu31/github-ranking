# E2E テスト: github-ranking

**この文書の役割:** ブラウザでページを開いて通しの操作を確かめる E2E（End to End＝端から端まで）テストの正本。道具の選定理由は [tech-stack.md](tech-stack.md)、どの操作を「なぜ」選んだかは [testing-design.md](testing-design.md) に書き、ここには書き写さない。

## 1. 目的
「利用者が実際にページを開いて行う操作（例: 開く → スクロール → ボタンを押す → 表示が変わる）が、本物のブラウザで壊れていないか」を確かめる。HTML の構文検査では分からない、読み込み・動き・コンソールのエラーを見る。

## 2. 範囲
- 主な画面を開いて、**コンソールのエラーが0件**であること
- 主な操作（リンク・ボタン・フォーム・アニメーションの開始）が期待どおりに動くこと
- 画面の幅（スマホ・PC）ごとに崩れていないこと（画像を残して目で見る）
- あわせて測るもの: アクセシビリティ（例: axe-core で WCAG 2.1 AA）・表示の速さ（[requirements.md](requirements.md) の §5 の値）

## 3. 構成
```
tests/
  conftest.py        # 共通の準備（ローカルのサーバーを立てる・ブラウザを開く）
  test_pages.py      # ページを開いてコンソールのエラー0件
  test_actions.py    # 操作のシナリオ
  results/           # 画像・動画（git に入れない）
```

## 4. 環境とテストデータ
- ページはローカルのサーバー（例: `python -m http.server`）で配り、テストの中で立てて片付ける
- 外部のサービス（フォームの送り先・地図など）には本番の宛先へ送らない。テスト用の宛先か、送信の手前で止める

成功したときも画像を残す（スマホ幅と PC 幅）。失敗したときは動画と操作の記録（trace）も残す。
